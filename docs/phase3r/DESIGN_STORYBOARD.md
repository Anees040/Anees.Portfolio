# Copper Atelier — visual storyboard

## Review first

Open `.qa/phase3r/blueprint/index.html` in Chrome, or run `node .qa/phase3r/board-server.mjs` and visit `http://127.0.0.1:3101`. The board is self-contained: local CSS, original geometric diagrams, copied approved images and the existing build's local font files. It is **seven composition studies, not the implemented website**. A global storyboard-position control switches representative start/middle/end stills; it does not pretend to be GSAP, pixel physics, a playable game or working AI. Missing original art is visibly labelled. Screenshots and measured review results live in `.qa/phase3r/evidence/blueprint/`.

## Direction: a copper thread through considered work

The continuous idea is **formation → person → useful products → hidden decisions → development → play → conversation**. One copper construction line recurs at section seams, not as a permanent fixed overlay. Backgrounds change as solid sliding planes. Type behaves differently at each moment. This is an expressive warm technical atelier, not a black neon developer demo or seven equal editorial cards.

Preserve Alabaster #F4F0E8, Graphite #252421, Copper #A85D3F, Antique Gold #C29A55, Dusty Clay #D7B9A5, Espresso #302B27, Linen #E7E0D5 and Mushroom #746D64. Small accent text/button fill uses approved #A2573A; light-surface supporting text uses #716A61. Display is Instrument Serif normal/italic, body/UI DM Sans, code/technology metadata IBM Plex Mono. No new brand primitive, neon, blur/glow, rainbow gradient, generic AI cartoon, cursor takeover or scroll lock.

The new brief permits **hero-local cosmic background points** as an exception to the previous blanket decorative-particle restriction. Keep them behind the portrait, sparse and bounded, with no nebula/glow/comet spectacle. Do not expand that exception across the site. Design-token changes, if ultimately necessary, require coordinator documentation and owner review in implementation, not here.

### Overall order and density

Proposed order: Hero → Personal Studio/About → Selected Work with integrated Digital Atelier views → Engineering/Workbook + preserved Concurrency Lab → Follow the Thread → Always Building → Evidence + Contact. Keep old section hashes functional. The old separate Digital Atelier becomes a compact project-inspection surface within Work; it is not silently discarded. Case studies remain distinct server routes. Avoid two adjacent long pins: engineering supplies a normal-flow reading interval between Work and Thread. Work pin travel targets at most ~2.7 available viewports; Thread targets five ~0.65 viewport chapter intervals, measured against readable content. These are caps, not mandatory empty scroll.

## 01 — Hero: Copper Cosmos

**Three beats:** start: an immediately legible image remains the safe default; enhancement samples and seeds a dispersed but silhouette-biased cloud only after image decode and capability checks. Middle: particles converge visibly from roughly 0.35–0.7 portrait widths of displacement over the existing 600ms hero/media interval (calibrate visually; do not conceal copy). End: a readable portrait holds; pointer repels nearby pixels and release reassembles. Initial assembly occurs once per actual mount, never every scroll re-entry; Replay is an explicit native button. No facial stretching/rigging.

**Exit:** the background horizon shifts up at most 6% while the following Linen plane covers it in normal scrolling; portrait does not explode every time a visitor scrolls. Background points can drift briefly during assembly/interaction, then settle. Offscreen/hidden/reduced motion stops both foreground and background.

**Assets:** `anees-idle.webp` is usable now; inherited light fringe must be judged against Graphite. A cleaner transparent export of the **same** approved artwork is preferred before final hero acceptance. The opaque original's checker pattern must never become sampled particles. Board particle stills are a silhouette/convergence cue only, not engine evidence.

## 05 — Follow the Thread: the copper loom

**Original world:** a horizontal drafting landscape of six stations. A single copper filament threads through a model grid, course records, daily schedule, local ledger, court concept and an open notebook. Foreground spool/guide geometry occludes the filament briefly; backplates travel more slowly than the foreground. No globe, buildings, walking Elliott avatar or fabricated employer timeline.

**Chapters:** Foundations, EduVerse, Sukoon, FitPilot, SportLynk, Current direction. This is a **thematic reading sequence**, not verified creation dates or progression in mastery. Existing source revisions verify project content, not chronology. The board explicitly labels this distinction. The current five theme destinations remain as compatibility anchors, not broken links.

**Scroll:** one measured, finite desktop sticky/pinned viewport; normalized progress chooses station + within-station progress. 0–0.2 reveals local artifacts; 0.2–0.72 is a reading hold; 0.72–1 transports the filament/foreground to the next station. All transforms, labels and line state derive from absolute progress so reverse scroll and hash jumps resolve identically. Frame positions are not accumulated. Last station releases to Always Building with the filament continuing into a flat baseline.

**Fallback:** vertical stations in DOM order with full text/screens and source links, visible complete route, no hidden chapters. Pin requires actual available height and measured text fit, not only a min-width query. No character sprites are required for the thread. This makes the experience independently implementable before new character art exists.

## 06 — Always Building: Deliver the build

**Original game proposal:** a short side-view workshop conveyor with three finite build stations: Record locally (FitPilot), Respect device state (Sukoon), Connect shared records (EduVerse). Player chooses the next build task and an approved Anees sprite carries a geometric work token across a gap to the next station. Arrival collects an evidence card, not +1 mastery. Complete three tasks to produce a small finished build slip and a link back to engineering. No leaderboard, fabricated skill percentages, punitive timer or mandatory play.

**Controls:** Start / next task / Pause / Restart, native buttons with focused-scene Space/Enter and named touch targets. No global key capture; vertical page scrolling remains available. The game state machine owns grounded → anticipation → airborne → landing → idle, token collision and completion. It is independent of scroll progress, activated explicitly, and pauses when hidden/offscreen.

**Art gate:** the available standing/working images are static, different canvases, not a run/jump atlas. The board therefore shows the standing pose as **placement only**, with an unfilled frame rail labelled Missing aligned anticipation / airborne / landing frames. Commission modest owner-approved frames with matching baseline/canvas; no auto-rig, invented motion or imported character. If art is not ready, postpone the animated game or obtain approval for an original geometric-token puzzle; do not ship a fake sprite game.

**Reduced motion:** equivalent task-choice/collection flow without movement, with a text log and evidence links. No play requirement to reach contact.

## 07 — Contact finale: the thread becomes a signature

The previous horizon flattens; a Copper line forms the existing MA signature on Espresso while a solid field wipes in. Serif contact heading is stationary and readable; one short word-line entrance follows the settled signature. Email and copy are large practical actions, GitHub is the verified second destination. No fictional LinkedIn/resume/contact availability promise. Evidence sits immediately before the finale. Ask Anees remains a planned-feature note with direct email fallback, not a simulated AI chat.

The final frame is a quiet stable Espresso plate: the entire journey resolves into a real way to contact the person. No perpetual rotating logo, floating social icons or particle shower.
